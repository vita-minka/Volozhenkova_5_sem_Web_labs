# Letters Evolution Stages

> Веб-сервис для датировки рукописей по палеографическим признакам

---

## О проекте

**Letters Evolution Stages** — учебный проект, разработанный в рамках курса «Разработка интернет-приложений» (МГТУ им. Н.Э. Баумана, кафедра ИУ-5).

Сервис помогает исследователям-палеографам определять **вероятный временной интервал создания рукописи** на основе анализа начертаний букв кириллицы. В основе — каталог **этапов-интервалов эволюции написания букв**: «ять», твёрдый знак «ъ», «фита» и других. Каждый этап привязан к веку и содержит эталонное описание признака, изображение и короткое видео с фрагментом рукописи.

Пользователь просматривает каталог этапов, изучает признаки и сопоставляет их с исследуемым текстом. Совокупность присутствующих и отсутствующих признаков позволяет сузить временной диапазон создания рукописи.

### Для кого

| Роль | Возможности |
|---|---|
| **Гость** | Просмотр ленты и каталога этапов, изучение признаков |
| **Исследователь (авторизованный)** | Всё то же + создание своих этапов, публикация, лайки, удаление |
| **Модератор** *(задел на будущее)* | Управление чужими карточками |

### Что уже реализовано

Проект прошёл четыре итерации разработки:

1. **Лаба 1** — SSR-интерфейс на NestJS + Handlebars с тремя страницами (лента, добавление, плитка) в мобильном формате 390×781
2. **Лаба 2** — перенос данных из массива в PostgreSQL через TypeORM, подключение MinIO для медиа, soft-delete
3. **Лаба 3** — REST API со всеми бизнес-методами, загрузка файлов через multipart, документация в Swagger
4. **Лаба 4** — сессионная авторизация через cookie + Redis, разграничение прав гостя и создателя

## Модель данных

Три таблицы с префиксом `letters_evolution_stages_` (доменный нейминг):

- **`letters_evolution_stages`** — сами этапы эволюции (название, описание, век, признак, ссылки на медиа, статус)
- **`letters_evolution_stages_users`** — пользователи (email, username, пароль, роль)
- **`letters_evolution_stages_likes`** — м-м связь «пользователь-услуга» (один лайк на пару, UNIQUE-ограничение)

Каскадное удаление **запрещено** — при удалении пользователя его услуги остаются, чтобы сохранить историю.

## HTTP API

| Метод | URL | Назначение | Доступ |
|---|---|---|---|
| GET | `/api/stages` | Список опубликованных с фильтром по веку | всем |
| GET | `/api/feed` | Одна карточка ленты (по id или первая) | всем |
| GET | `/api/stages/draft` | Черновик текущего пользователя | авторизованным |
| POST | `/api/stages` | Создать черновик с загрузкой файлов | авторизованным |
| PUT | `/api/stages/publish` | Опубликовать черновик | авторизованным |
| DELETE | `/api/stages/:id` | Мягкое удаление через SQL UPDATE | авторизованным |
| POST | `/api/stages/:id/like` | Поставить/снять лайк (`value: 0/1`) | авторизованным |
| POST | `/api/auth/register` | Регистрация | всем |
| POST | `/api/auth/login` | Вход (ставит cookie `sessionId`) | всем |
| POST | `/api/auth/logout` | Выход | авторизованным |
| GET | `/api/auth/me` | Текущий пользователь | авторизованным |

**Swagger:** http://localhost:3000/api/docs

## SSR-страницы

| URL | Описание |
|---|---|
| `/feed` | Лента: вертикальное видео на весь экран + описание + 2 поля по теме + лайк + стрелка «следующий» |
| `/add` | Создание черновика (при отсутствии) / публикация (при наличии) |
| `/stages` | Плитка 2 колонки с фильтром по веку и кнопкой удаления |
| `/login`, `/register` | Формы входа и регистрации |

## Особенности реализации

- **Сессионная авторизация** — при login сервер создаёт запись `session:<uuid> → userId` в Redis и устанавливает HttpOnly-cookie
- **Разграничение прав** — GET-методы публичны, POST/PUT/DELETE требуют валидной сессии (проверяется через `SessionGuard`)
- **Soft-delete** — удаление не физическое, а смена `status` на `deleted` через сырой SQL UPDATE
- **Курсор в SQL** — получение ленты одной строкой через `SELECT * FROM ... WHERE id = $1 AND status = 'published'`
- **MinIO** — файлы хранятся на S3-совместимом хранилище, в БД только имена файлов на латинице
- **Дефолтные медиа** — если URL в БД пуст, шаблон подставляет `/img/default-image.jpg` и `/img/default-video.mp4` с SSR-сервера
- **Мобильный формат** — все страницы в фиксированном 390×781 (как телефон)
- **Палитра** — `#EEEEEE` (фон), `#B59974` (акцент), `#504127` (кнопки), чёрная навигация

## Запуск проекта

### 1. Клонировать и установить зависимости

```bash
git clone <repo-url>
cd letters_evolution_stages
npm install
```

### 2. Поднять контейнеры

```bash
docker-compose up -d
```

Проверить:
```bash
docker ps
```

Должны быть 4 контейнера: `postgres_db`, `adminer_ui`, `minio_storage`, `redis_sessions`.

### 3. Запустить NestJS

```bash
npm run start:dev
```

### 4. Открыть в браузере

| Сервис | URL |
|---|---|
| Приложение | http://localhost:3000/feed |
| Swagger | http://localhost:3000/api/docs |
| Adminer | http://localhost:8081 |
| MinIO Console | http://localhost:9001 |
