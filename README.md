# Letters Evolution Stages — Backend

> REST API и SSR-сервис для датировки рукописей по палеографическим признакам

---

## О проекте

**Letters Evolution Stages — Backend** — серверная часть учебного проекта, разработанного в рамках курса «Разработка интернет-приложений» (МГТУ им. Н.Э. Баумана, кафедра ИУ-5).

Сервис помогает исследователям-палеографам определять **вероятный временной интервал создания рукописи** на основе анализа начертаний букв кириллицы. В основе лежит каталог **этапов-интервалов эволюции написания букв**: «ять», твёрдый знак «ъ», «фита» и других.

> ⚠️ **Важно:** Данный репозиторий содержит **только Backend-часть** (API + SSR).
> Клиентская часть (SPA на React) находится в отдельном репозитории.

### Что реализовано (Лабы 1-4)

Проект прошёл четыре итерации разработки серверной части:
1. **Лаба 1** — SSR-интерфейс на NestJS + Handlebars (3 страницы в мобильном формате 390×781).
2. **Лаба 2** — Перенос данных из массива в PostgreSQL через TypeORM, подключение MinIO для медиа, soft-delete.
3. **Лаба 3** — Разработка REST API со всеми бизнес-методами, загрузка файлов через multipart, документация в Swagger.
4. **Лаба 4** — Сессионная авторизация через cookie + Redis, разграничение прав гостя и создателя (CRUD защищен).

## Модель данных

Три таблицы с префиксом `letters_evolution_stages_`:
- **`letters_evolution_stages`** — сами этапы (название, описание, век, признак, ссылки на медиа, статус).
- **`letters_evolution_stages_users`** — пользователи (email, username, пароль, роль).
- **`letters_evolution_stages_likes`** — м-м связь (один лайк на пару, UNIQUE).

*Каскадное удаление запрещено — при удалении пользователя его услуги остаются.*

## HTTP API (REST)

| Метод | URL | Назначение | Доступ |
|---|---|---|---|
| GET | `/api/stages` | Список опубликованных с фильтром по веку | всем |
| GET | `/api/feed` | Одна карточка ленты | всем |
| GET | `/api/stages/draft` | Черновик текущего пользователя | авторизованным |
| POST | `/api/stages` | Создать черновик с загрузкой файлов | авторизованным |
| PUT | `/api/stages/publish` | Опубликовать черновик | авторизованным |
| DELETE | `/api/stages/:id` | Мягкое удаление через SQL UPDATE | авторизованным |
| POST | `/api/stages/:id/like` | Поставить/снять лайк | авторизованным |
| POST | `/api/auth/register` | Регистрация | всем |
| POST | `/api/auth/login` | Вход (ставит cookie `sessionId`) | всем |
| POST | `/api/auth/logout` | Выход | авторизованным |
| GET | `/api/auth/me` | Текущий пользователь | авторизованным |

**Swagger:** http://localhost:3000/api/docs

## SSR-страницы (Handlebars)

| URL | Описание |
|---|---|
| `/feed` | Лента: видео на весь экран + поля по теме + лайк |
| `/add` | Создание / публикация карточки |
| `/stages` | Плитка 2 колонки с фильтром по веку |
| `/login`, `/register` | Формы входа и регистрации |

## Особенности реализации

- **Сессионная авторизация** — `session:<uuid> → userId` в Redis + HttpOnly-cookie.
- **Разграничение прав** — GET-методы публичны, POST/PUT/DELETE защищены `SessionGuard`.
- **Soft-delete** — смена `status` на `deleted` через сырой SQL UPDATE.
- **Курсор в SQL** — получение ленты одной строкой.
- **MinIO** — файлы на S3, в БД только имена файлов.
- **Дефолтные медиа** — если URL пуст, подставляются `/img/default-*`.
- **Мобильный формат** — все страницы 390×781, палитра `#EEEEEE`, `#B59974`, `#504127`.

## Запуск проекта

### 1. Клонировать и установить зависимости

```bash
git clone <repo-url>
cd letters_evolution_stages_second_lab
npm install
```

### 2. Поднять контейнеры

```bash
docker-compose up -d
```

Проверить:
```bash
docker ps
```

Должны быть 4 контейнера: `postgres_db`, `adminer_ui`, `minio_storage`, `redis_sessions`.

### 3. Запустить NestJS

```bash
npm run start:dev
```

### 4. Открыть в браузере

| Сервис | URL |
|---|---|
| Приложение (SSR) | http://localhost:3000/feed |
| Swagger (API) | http://localhost:3000/api/docs |
| Adminer | http://localhost:8081 |
| MinIO Console | http://localhost:9001 |
